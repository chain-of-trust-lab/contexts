Chain of Trust contexts

JSON-LD contexts for the verifiable credentials of the master thesis "Enhancing Software Supply Chain Security Through Verifiable Identity Chains and Impersonation Prevention" (TU Berlin).

RoleCredential v1

Grants an actor (person, stage or service) one role in the pipeline of one repository.

Context
https://chain-of-trust-lab.github.io/contexts/role/v1.jsonld
Vocabulary
Role vocabulary v1: the meaning of each term, the actor types and the possible roles.
JSON Schema
https://chain-of-trust-lab.github.io/contexts/role/v1.schema.json checks a credential, including that the actor type fits the role.
Examples
The seven role credentials of the end-to-end example.

ProvenanceCredential v1

Records one pipeline step done to one artifact (a commit, a package or an image), linked to the run's previous credential.

Context
https://chain-of-trust-lab.github.io/contexts/provenance/v1.jsonld
Vocabulary
Provenance vocabulary v1: the nine step types, their issuer roles, artifact types and fields.
JSON Schema
https://chain-of-trust-lab.github.io/contexts/provenance/v1.schema.json checks a credential, including the fields that belong to its step type.
Examples
The nine credentials of one pipeline run in the end-to-end example, and invalid ones the schema rejects.

Role and provenance

The deploy gate trusts a provenance credential only if its issuer holds the role credential for that step.

End-to-end example

One consistent scenario for chain-of-trust-lab/rest-api: the organization gives seven agents their role credentials, then one pipeline run issues the nine provenance credentials of one commit, each by the agent that holds the step's role. The data is made up but fits together, and every credential is signed, with example keys that are not on any ledger.
