Provenance vocabulary v1

Terms of the ProvenanceCredential v1 context. Credentials are checked with the ProvenanceCredential v1 JSON Schema; there are signed examples of each type.

A role credential says who may act. A provenance credential says what was done to an artifact: its subject is the artifact, its issuer the agent of the actor that did the step.

ProvenanceCredential

Class. Records one pipeline step done to one artifact. Its type lists VerifiableCredential, ProvenanceCredential and exactly one of the step types below. It is signed with Ed25519Signature2018 by the issuer's did:sov DID and sent to the project agent, which holds the run's chain.

The subject's fields id, type, name, digest, step and pipelineRun are always present; the table gives the rest.

Artifact types

The value of credentialSubject.type and of each inputs item's type.

SourceRevision
A git commit. id is urn:git:sha1:<commit>, digest sha1:<commit>, name the repository URL.
Package
A built package. id is urn:sha256:<digest>, digest sha256:<digest>, name its Maven purl.
DeployableImage
A container image. id is urn:sha256:<digest>, digest sha256:<digest>, name its image reference.

Artifact properties

name
The artifact's name: a repository URL, a Maven purl or an image reference.
digest
The artifact's digest: sha1:<hex> for a commit, sha256:<hex> otherwise. It must match the artifact's id.
location
Where a publish step put the artifact.
inputs
The artifacts the subject was built from, each with id, type, name and digest: the commit of a package, the package of an image.

Run properties

step
The name of the pipeline step, as in the table above.
previousCredential
The run's previous provenance credential: its id and credentialDigest. Absent only on SourceCommittedCredential.
credentialDigest
sha256: followed by the sha256 of the RFC 8785 (JCS) canonical JSON of the previous signed credential, proof included.
pipelineRun
The run attempt that did the step. id is the attempt's URL, https://github.com/<owner>/<repo>/actions/runs/<runId>/attempts/<runAttempt>.
repository
The repository of the run, as its GitHub URL. It matches the scope of the issuer's role credential.
workflow
The path of the workflow file, for example .github/workflows/chain.yml.
workflowDigest
sha256:<hex> of the workflow file the run used.
runId
The GitHub Actions run ID, as a string.
runAttempt
The attempt number, as a string, starting at 1.

Step properties

sbomDigest
sha256:<hex> of the software bill of materials produced with the package.
result
The outcome of a test step: Passed or Failed.
reportDigest
sha256:<hex> of the test report: the unit-test report for PackageBuiltCredential, whose step compiles, runs the unit tests and packages; the step's own report for the tested credentials.
registry
The registry a publish step published to, as its URL, for example https://ghcr.io.
decision
The Release Approver's decision: Approved or Rejected.
environment
The environment an image is approved for or deployed to: Staging or Production.

What the verifier checks

The JSON Schema checks each credential's shape: the step, artifact type and fields that belong to its type. It cannot check:

  • who issued the credential: the verifier checks that the issuer holds a role credential with the step's issuer role and a scope equal to pipelineRun.repository
  • that id and digest name the same artifact, and that inputs and previousCredential point to credentials of the same run
  • the signature, the credentialDigest links, or the order of the steps

ACA-Py does not check the JSON Schema either; the verifier must.
